# ｍやるゼ！連携 設計（CarePAY 側）

CarePAY を `careSupportPass / MedAdapt / Touchvoo` 等の介護インフラ群（ｍやるゼ！系）の上に乗せ、
**契約・回収・債権・請求書発行のレイヤー**を担う。本書はその連携設計のたたき台。

最終更新：2026-05-29

> タイミング：実連携の着手は **クロテ凍結（medadapt）終了＝2026-06-09 以降**。それまでは設計のみ。本書は medadapt のコードには触れない前提。

---

## 役割分担

| レイヤー | 担当 | 内容 |
|---|---|---|
| 現場業務・介護記録・利用者マスタ | ｍやるゼ！系（careSupportPass 等） | 入居者・サービス実績・利用料の元データ |
| 契約・同意・回収・債権・請求書発行 | **CarePAY** | 口座振替/カード、未収管理、業態別の請求書・領収書 |
| 決済基盤 | Square（カード）＋ 収納代行（口振） | 実際のお金の動き |

CarePAY は「決済の上」を取る（Stripe 的ポジション）。元データは ｍやるゼ！から受け取り、回収まで一気通貫で握る。

---

## 連携方式（推奨：イベント＋参照API）

1. **利用者マスタ同期**：ｍやるゼ！の入居者・契約者（家族）情報を CarePAY の `residents` に同期。
   - 初期：CSV/バッチ取込。本番：Webhook（入居・退居・契約変更）＋ 参照API。
2. **利用料の確定イベント**：月次でサービス実績から請求額が確定 → ｍやるゼ！が CarePAY へ「請求確定」イベントを送る → CarePAY が `billing/run` で請求発行。
3. **回収結果の返却**：CarePAY の入金/未収/督促ステータスを ｍやるゼ！へ返す（施設の管理画面で突合できる）。
4. **ID 連携**：施設・利用者の ID を相互マッピング（`facilities.id` ↔ ｍやるゼ！施設ID、`residents.id` ↔ 利用者ID）。

---

## データマッピング（最小）

| ｍやるゼ！ | CarePAY |
|---|---|
| 施設 | `facilities`（biz_type / invoice_reg_no / collector を CarePAY 側で保持） |
| 入居者・契約者 | `residents`（pay_method・同意署名・Square card_id は CarePAY 側） |
| 月次利用料明細 | `billing/run` の入力（period / amount / 税区分） |
| 入金・督促状況 | `invoices.status` / `dunning_logs` を返却 |

---

## 認証・境界

- サービス間は **mTLS or 署名付きトークン**。利用者個人情報は最小限のみ越境（氏名・続柄・連絡先・口座/カードは CarePAY 保管、カード番号は Square のみ）。
- 監査ログ：同意取得（署名・日時・IP・端末）は CarePAY 側で保持し、ｍやるゼ！へ参照可能にする。
